# Merging the dragonayzer userscript localization

Source: "NekoRPG Game Text Localizer" v16.7, a Tampermonkey userscript by dragonayzer (`@namespace dragonayzer.userscripts`). It translates the live Chinese game at runtime. This document records how its tables map onto `translations/glossary/*.json`, what overlapped, what was imported, and what was left out. The import itself is `tools/merge-userscript.ts`; run it without `--apply` to regenerate the numbers below into `.tmp/merge/`.

## What the userscript contains

The file is 13.6k lines, of which roughly 11k are lookup tables generated by the author's `translation/build.py` from TSV files. The runtime code around them is a MutationObserver plus a throttled scan that walks text nodes panel by panel. Three toggles affect translation (`ENABLE_ITEM_NAMES`, `ENABLE_PROSE`, `ENABLE_NUMBER_FORMAT`); the other twenty-odd toggles are visual overrides (maxed skill bar styling, bestiary link colours, a zones tab, crafting tier prefixes, family roster scroll fixes) and are irrelevant here.

Tables, with key format and size:

| Table | Entries | Key | How the script uses it |
| --- | --- | --- | --- |
| `itemNames` | 517 | exact trimmed item or skill name | dictionary hit on the whole node, or on a candidate cut out before a comma, ` xN`, inside `[...]` or `"..."`, or before `: level` |
| `componentPairs`, `statPairs`, `realmPairs`, `slotPairs` | 11, 25, 17, 10 | Chinese substring | spliced into `buttons` lists; applied in order, longest first |
| `buttons` | 73 selectors, 361 pairs | CSS selector to ordered `[zh, en]` substring pairs | every pair applied by global replace inside the matched elements |
| `proseExact` | 4743 | exact trimmed text node | first stage of `applyProse`; a hit ends processing for that node |
| `proseFrag` | 3939 | arbitrary substring, longest first | one combined alternation regex, single pass, after exact and regex stages |
| `proseRegex` | 231 | anchored `^...$` pattern with `(.+?)` captures, replacement with `$1`, plus an `indexOf` hint | whole-node match; the first rule that changes the text wins |
| `bestiaryNames` | 526 | English enemy name to Chinese | reverse map so the game's bestiary hover handler can look up the original name |
| `partTiers` | 328 | displayed part name to tier number | crafting list prefix, visual only |
| `REALM_TIERS`, `REST_LOCATIONS`, `BACKWARD_LABELS` | 7, 12, 19 | English tier prefixes, location names, travel labels | visual overrides only |

Key normalisation before a lookup: `trim()`, then a retry on a "core" with leading quotes, colons, commas and dashes and trailing quotes stripped. Wrapper quotes are also stripped before the regex stage. Myriad units (万, 亿, 兆, ...) are converted to exponent form after translation, and the shipped English already carries converted figures for anything the author judged a stat rather than dialogue (changelog 13.5 to 13.8).

Two properties of the tables shape the whole merge:

1. Keys are DOM text nodes, not source literals. A source string with `<span>` or `<br>` inside it appears in the userscript as several keys, one per node. `proseFrag` exists because the game concatenates literals at runtime.
2. `proseFrag` keeps the source `${expression}` text verbatim in 10 template keys, and `proseRegex` encodes 231 more templates as regexes. Both can be converted to our `{{}}` skeleton format.

## Our side

`translations/glossary/*.json` is the hand-written layer. Keys are whole Chinese source strings as they appear in `src/*.js`, `src/islands/*.vue` and `index.html` (as extracted by `tools/split-catalog.ts` into `translations/gen/by-source/`). Tagged templates `` t`a ${x} b` `` are keyed by skeleton, `a {{}} b`, in `templates.json` (or any other glossary file; `activities.json` owns a few). A value may cite another term as `{{中文|English}}`; compile keeps the English half and drops the marker, so the citation is documentation, not a live lookup.

The compile (`bun run compile`) reports untranslated text in three places. `tools/extract-template-keys.ts` writes `"<!>"` into `templates.json` for a `t`-template with no English and prints how many. `tools/split-catalog.ts` writes `"<?>"` into `translations/gen/by-source/*.json` for a source string with no entry in `translations/source/catalog.raw.json` (the maxrau extraction). `tools/extract-glossary.ts` then either marks a glossary-owned key `"<!>"` there, or, for a `"<?>"` key, splices every known glossary term into the Chinese. That splice is what produces values like `移动极为Agility` and `Red TungstenHelmet` in `translations/en.full.json`. Those are not translations, and the merge treats them as empty.

Before the merge, of 6853 source strings: 793 glossary-owned, 1944 translated by catalog.raw, 1802 with no English at all, 2314 spliced or otherwise partly Chinese.

Layer to file mapping:

The layers overlap heavily with each other (an enemy name is in `bestiaryNames`, `proseExact` and often `proseFrag`), so the columns do not add up across rows. After de-duplication the userscript reaches 3565 of our source strings: 466 already translated the same way, 1736 translated differently, and the rest fills.

The 922 `proseExact` and 820 `proseFrag` keys that name no source string are DOM fragments: halves of a `<span>`-split sentence, single `<br>` lines of passages whose other lines were reflowed, and strings from the live site's newer content. They cannot be keyed in our system and were not imported.

## Where the two disagree

A reviewer compared 165 sampled prose conflicts (33 against glossary entries, 132 against catalog.raw) with the Chinese. 158 were style-only differences. Every hand-written glossary entry in the sample was semantically sound. Four catalog.raw entries had real errors on our side (a garbled name "Yqian" for 夜芊, the stat 铁质皮肤 "Iron Skin" paraphrased away, a swapped subject in 永远寻求着蓬勃生机的生命源泉, and 飞 "flee" rendered as "encounter"). Two userscript entries had real errors (百家人 as "Hundred-Clans people" where 百 is the surname, and 殿堂级 as "Hall-of-Fame" where it is a rank tier). One entry was flawed on both sides. Numbers, targets, multipliers and speaker tags were correct in every userscript entry checked.

Style, where they differ: the userscript writes large figures in exponent form ("2e7 Health", "1e11 XP") while catalog.raw writes "20,000,000" and "100 billion"; the userscript uses a single-character ellipsis and straight quotes; it keeps 【】 in English; it uses em dashes for interruptions; and it reflows `<br>` breaks to a fixed column width, which is why its multi-line keys do not line up with ours.

Vocabulary is the systematic gap. Userscript versus ours, most frequent first: Skyhigh-Tier / Ascendant Rank (云霄级), Furball / Fluffy (茸茸), Sky-Tier / Sky Rank (天空级), Family / Clan (家族), Peak / Pinnacle (巅峰), Restraint / Suppression (牵制), Crypt / Dungeon (地宫), Frostmarrow / Ice Marrow (冰髓), Rank N / Stage N (N阶), Aura / Halo (光环), Health / HP (生命), Cloth / Fabric (织料), Wheel Hub / Wheel Core (轮芯), Starmirror / Starlight (映星), Knife Coin / Blade Coin (刀币), Shaxue / Sayuki (纱雪), Aberrant Beast / Strange or Exotic Beast (异兽), Wildbeast / Wild Beast (荒兽), Warship / Ship (舰船), Fief / Domain or Territory (燕岗领), Technique / Arcane Art (秘法). The userscript is the more internally consistent of the two (one form per term); ours has drift inside catalog.raw (储存姬 appears three ways).

Which side wins. Existing English stays: both the glossary (hand-written, canon by definition) and catalog.raw (older, but reviewed as sound in 128 of 132 sampled cases). The userscript wins only where we had nothing: missing keys, `"<!>"` placeholders, and spliced compositions. Four catalog.raw entries are overwritten because the review showed them wrong; they are listed under "Overwrites" below. Imported prose is rewritten to our vocabulary with the substitution table described in the next section, so the fills do not reintroduce "Skyhigh-Tier" next to "Ascendant Rank".

## Mechanical mapping rules

`tools/merge-userscript.ts` parses the userscript with acorn, evaluates the table literals (including the `...statPairs` spreads inside `buttons` and the `Object.assign(Object.create(null), {...})` wrappers), and flattens them into layers. Layer priority when two layers translate one key differently: `itemNames`, `bestiaryNames`, `proseExact`, the pair arrays, `buttons`, `proseFrag`.

Matching a userscript key to one of our keys, in order:

1. Exact: the source string, or the source string trimmed, is a userscript key.
2. Unwrapped: the source string minus one outer wrapper element (and leading or trailing `<br>`) is a key. The wrapper is put back around the English.
3. `<br>` join: every Han line of a multi-line source string is an exact key. Accepted only when each English chunk ends the way its Chinese line ends (terminal punctuation for 。！？, a comma for ，, a `[speaker]` tag where the Chinese has one). 83 joins passed; 162 were rejected because the userscript reflowed the English by width and a line shared between two passages carries a chunk from the wrong one.
4. Template: the source template literal's skeleton (every `${...}` replaced by `{{}}`) matches a converted userscript template. Three sources of templates:
   - `proseFrag` keys containing `${`: converted when the English keeps the same expressions in the same order (10 of 10).
   - `proseRegex`: converted when the pattern is `^...$`-anchored, every capture is a plain wildcard (`(.+?)`, `(.*)`, `([\d.,]+)`), no regex syntax remains after unescaping, and the replacement uses `$1..$n` once each in order (220 of 231; the 11 skipped are unanchored, contain `[和与]` or `(,\s*)?` alternations, or count captures differently).
   - Label plus value: a skeleton whose single `{{}}` is at one end, with the label alone present as an exact key (`燕岗领排名: {{}}` from `燕岗领排名:`).

A match is then accepted, kept, or skipped:

- Skip if the userscript English is empty, still contains Chinese (2), has leading or trailing whitespace (28; those are concatenation glue like `" recovered "`), or the key is a single character (14; `峰`, `和`, the eight trigram names).
- Keep ours if the key already has glossary English or a catalog.raw translation (2202 keys, of which 1736 differ in wording).
- Overwrite only for keys listed in `.tmp/merge/overwrites.json` (16).
- Otherwise add. The English goes through the vocabulary substitution table (whole-word, case-sensitive, longest phrase first) and is written to the file chosen by the source file of the key.

Written files are re-serialised with two-space JSON and the file's existing line endings, so the diff is additions plus one lost blank separator line in `enemy_specs.json`.

## Vocabulary substitutions

A second review went through the 713 short keys where both sides have a translation and the wording differs (265 against glossary entries, 448 against catalog.raw), checked each candidate rewrite against the Chinese behind the actual fills, and produced `.tmp/merge/substitutions.json`: 102 ordered rules, longest phrase first, applied whole-word and case-sensitive to every imported string. They changed 338 of the 1331 imported entries. The most used: Furball to Fluffy (27), Illusory Realm to Illusion Realm (26), Skyhigh-Tier to Ascendant Rank (22), Deepfrost to Extreme-Cold (15), Bloodfall to Xuelo (14), Deepwood to Deep Forest (13), Crystallized to Crystalline (12), Hydrogen to Hydro (12), Wildbeast to Wild Beast (20 with the plural), Crypt to Dungeon (9).

Realm strings are handled as a ladder rather than term by term, because the userscript calls 级 "-Tier" and 阶 "Rank N" while `ranks.json` calls 级 "Rank" and 阶 "Stage N". So "Skyhigh-Tier Rank 3 Peak" becomes "Ascendant Rank Stage 3 Pinnacle" through three rules in sequence. Bare "Rank 7" through "Rank 9" are rewritten to "Stage N" because the userscript never uses "Rank" plus a digit for anything but 阶.

Rules the review considered and rejected, because the same English word covers a different Chinese term in the fills: bare Aura (战场气息 is "Battlefield Aura"), bare Family (17 of 20 uses are our own "Na Family"), Copper (the one hit is 铜板 coins), Intermediate (中等, which `ranks.json` does not cover), and bare Peak, Basic, Technique, Steel, Restraint, Puppet, Ruins.

Two style differences are left as the userscript wrote them and are listed under open decisions: exponent notation for large numbers and the single-character ellipsis.

Thirteen hand-written glossary values were changed by hand after the term review, because the glossary contradicted itself. None of these came from the userscript verbatim; the userscript only pointed at the collision.

- 牵制 was "Suppression" in `brackets.json`, the same word `enemy_specs.json` uses for 压制, and the imported dialogue contrasts the two affixes in one sentence ("don't you think 压制 is even more likely than 牵制 to become a burden"). 牵制 is now "Restraint" in all seven places: `brackets.json` (牵制, 牵制-从入门到精通, 牵制-从入门到入土), `enemy_specs.json` ([牵制], [牵制·祝福]), `templates.json` (牵制领悟度提升到了 {{}}%!, 要不是在荒兽森林我抢来了牵制药水的配方，). The `enemy_specs.json` description of 牵制 already said "Pinning the opponent down".
- 散华 was "Sublimation" in `brackets.json` (散华, 散华药剂) and `enemy_specs.json` ([散华], [散华^1/2]) while `enemy_specs.json` renders 散华·改 as "Scattered Bloom Mk. II". Now "Scattered Bloom" in all four.
- 天蚕丝 in `terms.json` was "Sky Silk", a mis-parse of 天蚕 (a silkmoth) plus 丝. Now "Wild Silk".
- 道具 in `brackets.json` was "Props". It is the equipment slot (`props_slot` in `index.html`), so now "Trinket".

Catalog.raw entries the term review flagged but that were left alone: 青年法师 "Adolescent Mage" (the userscript's "Young Mage" is already taken by 少年法师 in `brackets.json`, so fixing the age order means changing the hand-written entry too) and 万象天引B1 "Ten Thousand Phenomena Celestial Lure B1" (the userscript's "All-Phenomena Sky-Pull B1" is no better; the reference is Bansho Ten'in). Two `ui.json` labels the review called mistranslations were left as they are because they read like deliberate tab relabels: 背景信息 "Idle" (literally background information, userscript "Lore") and 消耗品 "Use" (consumables, userscript "Usable").

## Open decisions

- Numbers. 24 imported strings write large figures in exponent form ("2e7 Health", "the 【Ice Seal】 execution threshold is at 5.4e13 remaining HP"), matching the userscript's number formatter but not catalog.raw's "20,000,000". Either accept, or rewrite those 24 (grep `\de\d` in the glossary).
- Punctuation. 245 imported strings use the single-character ellipsis "…" (often doubled, mirroring the Chinese ……), 88 use an em dash for a Chinese ——, 93 keep 【】 around bracket terms. Catalog.raw uses "..." and keeps 【】 too. The bracket glossary handles 【】 either way.
- `enemies.json` as a separate file. The README paragraph is in place; if enemy descriptions should rather sit in `enemy_specs.json`, the file is a plain move.
- The four hand changes above (牵制, 散华, 天蚕丝, 道具) and the two `ui.json` labels left alone.
- 162 rejected `<br>` joins and the 922 unmatched `proseExact` keys are the largest pool of remaining userscript text. Recovering them means editing passages by hand with the userscript as a crib.
- Vocabulary drift inside our own side that the review found and the merge did not touch: 冰原 as Tundra, Arctic, Glacial Plain and Ice Plains across four files; 万载冰髓 twice in `brackets.json` ("Ten-Thousand-Year Ice Marrow", "Eternal Ice Marrow Ingot"); 飞船 as Spaceship and Vessel; 茸茸 as Fluffy and Fluffball; 暴走 and 狂暴 both "Frenzy". Also the generator splices without a space ("Blood SlaughterSword", "Na FamilyTraining Grounds"), which is a `tools/extract-glossary.ts` matter.
